# LendWise — AI Loan Application & Approval Platform

LendWise is a full-stack demo lending website. An applicant fills in a 5-step application, a pre-trained **Random Forest** model scores their default risk, and the application is **APPROVED** (model class 0) or **REJECTED** (class 1) instantly. Loan officers get a protected dashboard with KPIs, charts, search/filter, decision overrides, a contact-message inbox and CSV export.

> LendWise is an ML-powered demo platform. Decisions are generated by a machine-learning model for educational purposes and are not an actual credit offer.

## Features at a glance

- **Applicants:** 5-step application with mobile OTP verification (draft kept if the tab reloads; loan-type cards preselect the purpose), live indicative EMI, instant decision page, PDF decision letter, print view, status lookup by ID + email, contact form, and emails for application receipt, decision and any officer update.
- **Officers:** KPIs and charts, searchable/filterable/sortable/paginated table, detail drawer with override or "under review" (note required, original model decision kept; the applicant is emailed, the note is never shared), permanent delete for data-deletion requests, CSV export, contact-message inbox with email replies, and an email outbox with previews.
- **Platform:** demo mode when the model is missing, "service temporarily unavailable" handling, rate limiting, security headers, request IDs, no PII in logs, SEO (metadata, Open Graph image, sitemap, robots), responsive from 360px, WCAG-minded accessibility.

## Architecture

```
 Browser ──► Next.js (App Router)  ──►  FastAPI /api/v1  ──►  preprocessing ─► RandomForest ─► decision ─► SQLite
            pages + /api/* route          (backend/app)        (ml/preprocessing.py)  (ml/predictor.py)  (ml/decision.py)
            handlers (server-side proxy)
```

```
lendwise/
├── backend/                  FastAPI + Python 3.11 (all ML lives here)
│   ├── app/
│   │   ├── main.py           app, CORS, security headers, request IDs, error format, lifespan model loading
│   │   ├── config.py         pydantic-settings (.env)
│   │   ├── db.py, models_db.py   SQLAlchemy 2.0 + SQLite (`applications`, `contact_messages`)
│   │   ├── schemas.py        Pydantic v2 validation (mirrors the frontend zod schema)
│   │   ├── auth.py           officer login (bcrypt + HS256 JWT)
│   │   ├── services.py       submit → predict → decide → persist
│   │   ├── ml/               preprocessing.py · predictor.py · decision.py · artifacts/
│   │   └── routers/          health · metadata · applications · contact · admin
│   ├── scripts/
│   │   ├── build_artifacts.py   rebuilds the missing StandardScaler + metadata, verifies metrics
│   │   └── seed_demo.py         optional sample applications for the dashboard
│   ├── tests/                pytest (preprocessing, parity, decision, API, demo mode)
│   └── Dockerfile
├── frontend/                 Next.js 16, TypeScript, Tailwind v4, shadcn/ui (Base UI), RHF + zod, recharts
│   └── src/app/api/*         route handlers: the browser never talks to FastAPI directly
└── docker-compose.yml
```

- The browser only calls same-origin `/api/*` route handlers; they call FastAPI server-side (`BACKEND_API_URL`). The `.pkl` never leaves the backend.
- Officer JWTs live in an **httpOnly, SameSite=Strict** cookie set by the Next.js route handler. A rejected token (expired, forged, or after rotating `JWT_SECRET`) is cleared automatically.
- After submitting, the browser receives a private **httpOnly cookie** per application so it can reopen its own decision page. Anyone else needs the application ID **and** the email (IDs are sequential, so they're never enough on their own).

## ML pipeline

1. 11 raw inputs → `engineer_features` (Income_per_Experience, Age_Group, Career_Stability, Experience_Ratio, Financial_Maturity, Long_Term_Resident, Career_Start_Age, Stable_Employee)
2. Single-row one-hot encoding over the model's exact 414 `feature_names_in_` (no `get_dummies` on one row; baseline categories → all zeros; `[`, `]`, `<` stripped)
3. `StandardScaler` on the 10 numeric columns only
4. `model.predict` → class → decision; `predict_proba` → default probability, approval score, confidence, risk band (Low < 0.30 ≤ Moderate < 0.50 ≤ High)
5. Indicative factors = plain-language comparisons of engineered features against training medians (labelled *indicative*, not explanations)

Loan amount, tenure and purpose are recorded and used for the indicative EMI only — **they are not model inputs**, and the UI says so.

## Local setup

**Prerequisites:** Python 3.11 (scikit-learn 1.6.1 has no wheels for 3.13+), Node 20+ (22 recommended). [`uv`](https://docs.astral.sh/uv/) is the easiest way to get Python 3.11.

### 1. Model & dataset placement

| File | Location | In git? |
|---|---|---|
| Trained model (~127 MB) | `backend/app/ml/artifacts/model.pkl` | ❌ (too large) |
| Dataset (Kaggle `subhamjain/loan-prediction-based-on-customer-behavior`) | `backend/data/Training Data.csv` | ❌ |
| `scaler.pkl`, `feature_columns.json`, `metadata.json` | `backend/app/ml/artifacts/` | ✅ (small; generated) |
| SQLite DB | `backend/lendwise.db` | ❌ |

If the CSV is missing, `build_artifacts.py` downloads it when `KAGGLE_USERNAME`/`KAGGLE_KEY` are set; otherwise it prints instructions and exits non-zero.

### 2. Backend

```bash
cd backend
uv venv --python 3.11 .venv          # or: python3.11 -m venv .venv
uv pip install --python .venv/bin/python -r requirements.txt   # or: .venv/bin/pip install -r requirements.txt
cp .env.example .env                 # then edit secrets
.venv/bin/python scripts/build_artifacts.py   # rebuilds scaler.pkl + metadata.json and prints metrics
.venv/bin/python -m pytest -q        # 57 tests incl. 200-row single-vs-batch parity
.venv/bin/uvicorn app.main:app --port 8000
.venv/bin/python scripts/seed_demo.py --count 30   # optional: sample applications for the dashboard
```

API docs: <http://localhost:8000/docs> (ReDoc at `/redoc`). To start from an empty database, stop the API and delete `backend/lendwise.db`.

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env.local
npm run dev            # http://localhost:3000
# production: npm run build && npm run start
```

### 4. Docker

```bash
cp backend/.env.example backend/.env    # edit secrets
docker compose up --build               # web → http://localhost:3000, API → http://localhost:8000/docs
# ports busy? FRONTEND_PORT=3100 BACKEND_PORT=8100 docker compose up --build
```

`model.pkl` must be present in `backend/app/ml/artifacts/` before building (or set `MODEL_URL`, see below). SQLite lives in the `lendwise-data` volume. The backend image needs **≥ 1 GB RAM**.

### Emails and phone OTP (demo vs live)

| | Demo (default, no keys) | Live |
|---|---|---|
| **Email** | Every email is rendered and stored in the outbox. Applicants see theirs on the decision page; officers see all of them under **Email outbox**. Nothing is delivered. | Set `RESEND_API_KEY` and `EMAIL_FROM` (a sender on a domain verified in Resend). Emails are delivered in the background; failures are recorded and shown in the outbox. |
| **Phone OTP** | The 6-digit code is generated by the API and shown on screen with a clear "Demo mode — no SMS is sent" note. | Set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `TWILIO_VERIFY_SERVICE_SID`. Twilio Verify sends and checks the SMS code. |

Both modes use the same rules: codes expire after 10 minutes, 5 wrong attempts lock a code, a 30-second resend cooldown and a 5-per-hour cap per number apply, and a successful check returns a signed token (valid 30 minutes) that the application must carry. `GET /api/v1/health` reports `email_mode` and `sms_mode`. Set `REQUIRE_PHONE_VERIFICATION=false` to make OTP optional.

### Demo mode (model)

If `model.pkl` or `scaler.pkl` is missing, the API still starts with `mode: "demo"`: decisions come from a deterministic heuristic, are saved with `is_demo = true`, carry a warning, and the site shows **“Demo mode — ML model not loaded”**. Demo output is never presented as a model decision.

## API (`/api/v1`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/health` | – | status, model_loaded, mode, model_version |
| GET | `/metadata` | – | dropdown options, state→cities, ranges, metrics |
| POST | `/applications` | – (rate-limited) | validate → predict → decide → save; 201 with decision |
| GET | `/applications/{id}/status?email=` | – (rate-limited) | public status check (ID **and** email) |
| GET | `/applications/{id}` | `X-Access-Token` | decision for the submitting browser (token held in httpOnly cookie) |
| POST | `/otp/send`, `/otp/verify` | – (rate-limited) | phone OTP; verify returns the token required by `POST /applications` |
| POST | `/contact` | – (rate-limited) | contact form → officer inbox + acknowledgement email (returns `LW-MSG-…` reference) |
| POST | `/admin/messages/{id}/reply` | JWT | email a reply to the sender (optionally mark resolved) |
| GET | `/admin/emails` | JWT | email outbox (filter by application or message) |
| POST | `/admin/login` | – | officer JWT |
| GET | `/admin/applications` | JWT | pagination, search (name/ID), filters (decision, risk band, status, dates), sort |
| GET/PATCH | `/admin/applications/{id}` | JWT | detail; override decision / mark under review (note required; model decision retained) |
| DELETE | `/admin/applications/{id}` | JWT | permanently delete (data-deletion requests) |
| GET | `/admin/stats` | JWT | totals, rates, avg default prob., per-day, histogram, by profession/state |
| GET | `/admin/applications/export.csv` | JWT | CSV export (formula-injection safe) |
| GET / PATCH | `/admin/messages`, `/admin/messages/{id}` | JWT | officer inbox; mark resolved / reopen |

Errors always look like `{"error": {"code", "message", "details": [{field, message}], "request_id"}}`. Every response carries `X-Request-ID`.

## Deployment

**Backend → Render / Railway (≥ 1 GB RAM instance)**
- Root directory `backend/`, Docker deploy using `backend/Dockerfile`.
- Provide the model: commit it with Git LFS, bake it into the image, or set `MODEL_URL` (+ `MODEL_SHA256`) to a private download link.
- Database: set `DATABASE_URL` to Postgres. For Supabase, use **Connect → Direct → Session pooler** (IPv4-compatible). `postgresql://` URLs are accepted as-is; the driver (`psycopg`) and `sslmode=require` are applied automatically, and tables are created on first start. Without Postgres, attach a persistent disk at `/data` for SQLite.
- Memory: the API peaks at about 340 MB with the model loaded, so a 512 MB instance is enough (1 GB gives headroom).
- Set `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `CORS_ORIGINS=https://<your-vercel-domain>`.
- Keep the API reachable only by the frontend if possible. The per-IP limiter uses the client IP forwarded by the Next.js server (`x-real-ip` / `X-Forwarded-For`), which is trustworthy behind Vercel or a load balancer; a global per-minute cap backs it up when self-hosting.

**Frontend → Vercel**
- Root directory `frontend/`, framework Next.js.
- Env: `BACKEND_API_URL=https://<your-backend>` and `NEXT_PUBLIC_SITE_URL=https://<your-domain>`.

## Limitations & fairness

The model sees no credit-bureau data, and features such as city, state and profession can encode historical bias. Loan amount is not a model input. Officers can review and override any decision, and the original model decision is always kept.
